## Fuente oficial y alcance

Se leyó el encargo y la pauta completa del PDF oficial [Evaluacion_Parcial_2_Encargo_y_Presentacion_Requerimientos(1).pdf](../Evaluacion_Parcial_2_Encargo_y_Presentacion_Requerimientos(1).pdf), de 10 páginas. La evaluación corresponde a Desarrollo Cloud Native I (DSY1107), año 2026.

La pauta del **encargo** pondera: nombres centralizados 12%; topología declarativa 13%; separación de configuración y lógica 10%; consumidores por dominio 15%; ACK, errores, DLQ, duplicados y logs 20%; API REST administradora 13%; encapsulación de administración en servicio 17%.

La pauta de la **presentación** pondera: recursos AWS operativos 15%; dos instancias consumidoras 15%; tres colas con usos distintos 7%; DLQ por cola 9%; fanout y filtros 6%; integración productor-consumidor 10%; logs de mensajes no entregados 8%; operación del administrador 12%; métricas y alarma 8%; retención y limpieza justificadas 10%. La demostración debe hacerse en la consola AWS; la plantilla no es evidencia suficiente.

El PDF también exige mantener la integración del Parcial 1 (RDS, Cognito y API Manager), código compilable, repositorio GitHub único, commits de ambos integrantes y ausencia de credenciales AWS en el repositorio. Por instrucción del usuario, esos componentes existentes no se reconstruyen ni modifican sin un defecto demostrado.

## Cambios locales tras la auditoría

- El consumidor registra el mensaje como procesado/duplicado solo después de que `DeleteMessage` termine sin error.
- El log de envío no recuperable a DLQ se emite después de que `SendMessage` haya tenido éxito. Si falla, el mensaje original no se borra.
- El consumer toma el long polling de la cola declarada, no anula el valor de 20 segundos con un sondeo explícito de 2 segundos.
- `maxReceiveCount` se centralizó en la propiedad `SQS_MAX_RECEIVE_COUNT`, el servicio administrador y el parámetro `MaxReceiveCount` de CloudFormation.
- La suscripción administrativa preserva las declaraciones preexistentes de la política SQS al agregar permiso limitado por `aws:SourceArn`.
- Se añadió documentación de ejecución de workers y `.env`/`.env.*` a `.gitignore` del backend.
- Se creó `infra/aws-skates-messaging.yaml`, una plantilla separada que no incluye RDS ni servicios ajenos a mensajería. Parseo y comprobaciones estructurales locales aprobados; no desplegada.
